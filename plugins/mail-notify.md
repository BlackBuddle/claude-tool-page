# 메일 알림(mail-notify) 안내

Gmail이나 Outlook에 안 읽은 메일이 새로 오면 ClaudeTool의 펫이 알려 주고, 말풍선의 버튼으로 그 메일을 바로 열게 하는 플러그인입니다. 하루에 한 번 안 읽은 메일 수를 요약해 주기도 합니다. 쓰는 것은 두 가지입니다.

- **플러그인 zip** (`mail-notify.zip`): 안 읽은 메일을 주기적으로 확인해 펫 신호·말풍선·Windows 알림으로 알립니다.
- **캐릭터 zip** (`choux-desk-pack.zip`): 알림 종류마다 다른 몸짓을 하는 캐릭터입니다. 없어도 알림은 옵니다.

Gmail과 Outlook 중 쓰는 쪽만 연결하면 됩니다. 둘 다 연결해도 됩니다. 메일은 **읽기만** 합니다. 읽음 처리·삭제·답장은 하지 않고, 메일 본문도 읽지 않습니다. 보낸 사람·제목·받은 시각만 봅니다.

## 준비물

- **ClaudeTool 0.4.2 이상**. 이 플러그인은 0.4.2에서 생긴 권한(토큰 보관, Windows 알림, 링크 열기, 클립보드 쓰기)을 씁니다.
- **zip 두 개**: 플러그인 `mail-notify.zip`과 캐릭터 `choux-desk-pack.zip`을 [릴리스](https://github.com/BlackBuddle/claude-tool-page/releases/tag/plugins-2026-10)에서 받습니다. 릴리스 노트의 SHA-256 값과 비교해 보세요.
- **Gmail을 쓸 때**: 아래 "Gmail 연결 준비"로 클라이언트 ID·클라이언트 보안 비밀·갱신 토큰을 만듭니다.
- **Outlook을 쓸 때**: 아래 "Outlook 연결 준비"로 앱을 등록하고 클라이언트 ID를 얻습니다.

화면 이름과 메뉴 위치는 Google과 Microsoft가 바꿀 수 있습니다. 이름이 조금 달라도 같은 항목을 찾으세요.

### Gmail 연결 준비

Gmail에는 "비밀번호로 읽기"가 없어서, 본인이 직접 OAuth 클라이언트를 만들고 갱신 토큰을 한 번 받아야 합니다. 개인용이라 Google의 앱 검증은 필요 없습니다.

1. https://console.cloud.google.com 에 Google 계정으로 로그인하고, 위쪽 프로젝트 선택 › 새 프로젝트에서 `ClaudeTool 메일` 같은 이름으로 프로젝트를 만듭니다.
2. 왼쪽 메뉴 API 및 서비스 › 라이브러리에서 `Gmail API`를 찾아 **사용**을 누릅니다.
3. API 및 서비스 › OAuth 동의 화면(새 화면에서는 Google Auth platform)에서 앱 이름(`ClaudeTool 메일`)과 본인 이메일을 적고 대상(Audience)을 **외부**로 만듭니다. 데이터 액세스(범위)에서 범위 추가를 눌러 `https://www.googleapis.com/auth/gmail.readonly` 하나만 넣습니다.
4. **프로덕션으로 게시합니다.** 대상(Audience) 화면의 "앱 게시"를 눌러 상태를 "테스트"에서 "프로덕션"으로 바꿉니다. 테스트 상태로 두면 갱신 토큰이 **7일 뒤 만료**되어 매주 다시 받아야 합니다. 게시한 뒤에 아래 6번의 토큰을 받으세요. 게시 전에 받은 토큰은 7일짜리입니다.
5. 사용자 인증 정보(클라이언트) › 만들기 › OAuth 클라이언트 ID에서 애플리케이션 유형을 **웹 애플리케이션**으로 고르고, "승인된 리디렉션 URI"에 `https://developers.google.com/oauthplayground` 를 추가한 뒤 만듭니다. 화면에 나오는 **클라이언트 ID**와 **클라이언트 보안 비밀**을 복사해 둡니다.
6. https://developers.google.com/oauthplayground 를 엽니다.
   1. 오른쪽 위 톱니(OAuth 2.0 configuration)를 누르고 **Use your own OAuth credentials**를 체크한 뒤 위 5번의 클라이언트 ID와 보안 비밀을 넣습니다. 이 자격을 쓰지 않으면 토큰이 24시간 뒤 폐기됩니다.
   2. 왼쪽 Step 1의 범위 입력 칸에 `https://www.googleapis.com/auth/gmail.readonly` 를 넣고 **Authorize APIs**를 누릅니다.
   3. 계정을 고르면 "Google에서 확인하지 않은 앱" 경고가 뜹니다. 본인이 만든 앱이므로 고급 › (앱 이름)(안전하지 않음)으로 이동을 눌러 메일 읽기를 허용합니다.
   4. Step 2에서 **Exchange authorization code for tokens**를 누르면 **Refresh token**이 나옵니다. 복사해 둡니다.

세 값(클라이언트 ID·보안 비밀·갱신 토큰)은 아래 "③ 설정 칸 채우기"에서 비밀 칸 3개에 붙여 넣습니다. 복사해 둔 값은 비밀번호처럼 다루세요. 문서·채팅·메모에 남기지 말고 붙여 넣은 뒤에는 지우세요. 새어 나갔다고 의심되면 Google 계정에서 이 앱의 서드파티 접근 권한을 해제하고, Google Cloud 콘솔의 OAuth 클라이언트에서 클라이언트 보안 비밀을 재설정한 다음 새 갱신 토큰을 받아 칸을 바꾸세요.

### Outlook 연결 준비

Outlook(개인 Microsoft 계정 포함)은 로그인 코드를 입력하는 방식(기기 코드 흐름)으로 연결합니다. 비밀 값을 손으로 옮길 필요가 없고, 플러그인이 받은 갱신 토큰을 이 PC에 암호화해 보관합니다. 다만 Microsoft Entra에 앱을 하나 등록해 클라이언트 ID를 얻어야 합니다.

1. https://entra.microsoft.com 에 Microsoft 계정으로 로그인하고 앱 등록(App registrations) › 새 등록을 누릅니다.
2. 이름은 `ClaudeTool 메일`, 지원되는 계정 유형은 **모든 조직 디렉터리의 계정 및 개인 Microsoft 계정**을 고릅니다. 리디렉션 URI는 비워 둔 채 등록합니다.
3. 개요 화면의 **애플리케이션(클라이언트) ID**를 복사합니다.
4. 인증(Authentication) › 고급 설정에서 **공용 클라이언트 흐름 허용**을 "예"로 바꾸고 저장합니다.
5. API 사용 권한 › 권한 추가 › Microsoft Graph › 위임된 권한에서 `Mail.Read`와 `offline_access`를 골라 추가합니다.

회사·학교 계정은 조직 관리자가 앱 동의를 막아 둘 수 있습니다. 그 경우 관리자 허용이 필요합니다.

## 설치

### ① 플러그인 zip 가져오기

1. ClaudeTool 설정 창 › 🧩 플러그인 › ＋ 가져오기(.zip)를 눌러 받은 `mail-notify.zip`을 고릅니다.
2. 동의 창이 뜹니다. 아래 줄이 보이는지 확인하고, 괜찮으면 설치합니다.
   - 말풍선을 띄워요
   - 로그인 정보(토큰·키)를 이 PC에 암호화해 보관해요
   - Windows 알림을 띄워요
   - 사용자가 누른 링크를 브라우저로 열어요
   - 글을 클립보드에 복사해요
   - `https://oauth2.googleapis.com`
   - `https://gmail.googleapis.com`
   - `https://login.microsoftonline.com`
   - `https://graph.microsoft.com`
3. 카드가 "실행 중"이 되면 설치는 끝입니다.

링크는 말풍선의 [열기]를 눌렀을 때만 열리고 https 주소만 열립니다. 클립보드는 Outlook 로그인 코드의 [코드 복사]를 눌렀을 때만 씁니다. 인터넷으로 나가는 곳은 위 네 곳(Google·Microsoft의 로그인과 메일 서버)뿐입니다.

### ② 캐릭터 zip 가져오기(선택)

1. 설정 창 › 🐾 캐릭터 › ⤓ 가져오기(.zip)를 눌러 `choux-desk-pack.zip`을 고릅니다.
2. 가져온 캐릭터 "슈크림빵(책상)" 카드에서 "사용하기"를 누릅니다.

이 캐릭터는 신호 동작이 36개라 캐릭터 편집기의 기본 동작 한도(12개)보다 많습니다. 열기·저장·사용은 그대로 되지만, 편집하다가 새 동작을 더하려면 캐릭터 편집기 화면의 "동작 한도" 칸을 37 이상(예: 40, 최대 60)으로 올리세요(이 캐릭터는 36개라 한도가 36이면 더 못 넣습니다).

### ③ 설정 칸 채우기

설정 창 › 🧩 플러그인에서 `메일 알림` 카드를 고르고 칸을 채웁니다.

| 칸 | 설명 |
|---|---|
| Gmail 클라이언트 ID · 클라이언트 보안 비밀 · 갱신 토큰 | 위 "Gmail 연결 준비"에서 만든 세 값을 각각 붙여 넣습니다. 세 칸을 모두 채워야 Gmail을 확인합니다. 이 PC의 Windows 안전 저장소에 암호화해 보관하고, 설정 창에는 "저장됨"만 보입니다. Gmail을 안 쓰면 비워 둡니다. |
| Outlook 클라이언트 ID | 위 "Outlook 연결 준비"에서 복사한 애플리케이션(클라이언트) ID를 붙여 넣습니다. 넣은 뒤 설정 창 안의 [Outlook 로그인] 버튼을 누릅니다(아래 ④ 참고). Outlook을 안 쓰면 비워 둡니다. |
| 확인 간격(분) | 기본 3분(1~60). Gmail과 Outlook을 따로 이 간격으로 확인합니다. |
| 보낸 사람 규칙 | 줄마다 `<글자>=<동작>`을 씁니다(아래 "보낸 사람 규칙" 참고). |
| 하루 요약 시각(시) | 기본 -1(끔). 0~23을 적으면 그 시각이 지난 첫 확인에 안 읽은 메일 수를 하루 한 번 알립니다. |
| 새 메일·중요 메일·하루 요약 알림 | 종류별로 켜고 끕니다. 끈 종류는 신호·말풍선 없이 지나갑니다. |
| Windows 알림도 띄우기 | 말풍선과 함께 Windows 알림도 띄울지 정합니다. |
| 방해 금지 시작·끝(HH:MM) | 둘 다 적으면 그 시간 동안 온 소식을 모아 두었다가 끝나면 한 번에 알립니다. 자정을 넘겨도 됩니다(`22:00`~`07:00`). 한쪽만 적거나 모양이 틀리면 꺼 두고 설정 창에 이유를 보입니다. |

Gmail 세 칸을 채우면 곧바로 한 번 확인합니다. 설정 창 안의 "지금 확인" 버튼으로 언제든 다시 확인할 수 있습니다. 설정 창에는 계정별 연결 상태와 마지막 확인 시각이 보입니다.

**처음 확인은 알리지 않습니다.** 연결한 날 이미 쌓여 있던 안 읽은 메일이 한꺼번에 쏟아지지 않도록, 첫 확인에서 보이는 메일은 "이미 본 것"으로만 기록하고 설정 창에 그 수를 보입니다. 그 뒤에 새로 온 메일부터 알립니다. Gmail 설정 칸을 바꾸거나 Outlook에서 로그아웃하면 그 계정은 처음 확인부터 다시 합니다.

### ④ Outlook 로그인

1. 설정 창에서 `메일 알림` 카드의 [Outlook 로그인]을 누릅니다.
2. 펫 말풍선에 로그인 코드(`ABCD-EFGH` 같은 모양)와 [코드 복사]·[로그인 열기] 버튼이 뜹니다. 말풍선을 놓쳤으면 설정 창에도 같은 코드가 보입니다.
3. [로그인 열기]를 눌러 열린 Microsoft 페이지에 코드를 입력하고, 메일을 읽는 권한을 허용합니다. 코드는 15분 안에 입력해야 합니다.
4. 몇 초 뒤 설정 창에 "연결됨"이 보입니다. 이 PC에는 받은 갱신 토큰만 암호화해 저장합니다.

[Outlook 로그아웃]을 누르면 이 PC에 저장한 갱신 토큰을 지웁니다. Microsoft 쪽에 준 접근 권한은 Microsoft 계정의 앱 권한 화면에서 직접 해제하세요.

## 보낸 사람 규칙

보낸 사람 규칙 칸에 줄마다 `<글자>=<동작>`을 씁니다. 보낸 사람의 주소나 이름에 그 글자가 들어 있으면(대소문자 무시) 적용하고, 위에서부터 먼저 맞는 줄 하나만 씁니다. `#`으로 시작하는 줄은 주석입니다.

```
# 상사 메일은 중요 메일로
boss=important
# 인스타그램 알림 메일은 [SNS] 배지로
instagram=sns
# 뉴스레터는 알리지 않음
newsletter=mute
```

| 동작 | 효과 |
|---|---|
| `important` | 중요 표시가 없어도 중요 메일(`mail_important`)로 알립니다. |
| `sns` | 새 메일(`mail_new`)로 알리되 글머리를 `[SNS]`로 바꿉니다. |
| `mute` | 알리지 않습니다. 이미 본 것으로 기록하므로 규칙을 지워도 지난 메일이 갑자기 알림으로 오지는 않습니다. |

규칙이 맞는 메일은 규칙이 먼저입니다. 예를 들어 Gmail이 중요 표시를 붙인 메일이라도 `mute` 규칙에 맞으면 조용히 지나갑니다.

## 알림 종류와 펫 동작

| 알림 | 이럴 때 | 펫 동작(캐릭터 `choux-desk`) | 말풍선의 [열기] |
|---|---|---|---|
| 새 메일 | 안 읽은 메일이 새로 왔을 때 | `mail_new` — 봉투 배지 | 그 메일 |
| 중요 메일 | Gmail의 "중요" 표시, Outlook의 중요도 높음, 또는 `important` 규칙에 맞는 메일 | `mail_important` — 느낌표 배지와 빨간 화면 | 그 메일 |
| 메일 요약 | 하루 요약 시각이 지난 첫 확인(하루 한 번) | `mail_digest` — 목록 배지 | 없음 |

- 말풍선에는 `[Gmail] 보낸 사람 — 제목`처럼 보입니다. 중요 메일은 `[중요 Gmail]`, `sns` 규칙에 맞으면 `[SNS]`로 시작합니다.
- 같은 종류의 메일이 첫 메일에서 2분 안에 여러 통 오면 말풍선 한 장에 번호 붙은 목록으로 합치고, 통마다 [1번 열기]처럼 버튼이 생깁니다. 버튼은 5개까지고, 그보다 많으면 "…외 N통"으로 줄입니다. 중요 메일은 새 메일 묶음에 섞지 않고 따로 묶습니다.
- 요약은 최근 2일 안의 안 읽은 메일을 셉니다. 계정마다 한 번에 20통까지만 세므로 20통이 넘으면 "20통 이상"으로 보입니다. 0통이면 말풍선 한 줄만 뜨고 펫은 움직이지 않으며 Windows 알림도 없습니다.
- 말풍선은 닫기 버튼을 누르거나 60초가 지나면 닫힙니다. Windows 알림은 앱의 한도(분당 6개) 안에서만 뜹니다. 다른 캐릭터를 쓰면 이 동작이 없어 말풍선과 Windows 알림만 옵니다.

## 한계

- **읽기 전용입니다.** Gmail은 `gmail.readonly`, Outlook은 `Mail.Read` 범위만 씁니다. 보낸 사람·제목·받은 시각만 읽고, 이 PC 밖으로 나가는 것은 Google·Microsoft 서버로 보내는 요청뿐입니다.
- **실시간이 아닙니다.** 기본 3분마다 확인합니다. 최근 2일 안의 안 읽은 메일 20통까지 보므로, 2일이 지난 안 읽은 메일은 알리지 않습니다. 한 번에 새 메일이 많이 오면 Gmail은 10통씩 읽고 나머지는 다음 확인에서 읽습니다.
- **Gmail 갱신 토큰은 "프로덕션으로 게시"해야 오래 갑니다.** 앱이 "테스트" 상태면 7일마다 만료됩니다. 게시해도 사용자 100명 상한과 "확인되지 않은 앱" 경고가 붙지만, 본인 한 명이 쓰는 데는 문제없습니다.
- **Outlook 로그인은 90일 동안 안 쓰면 만료됩니다.** 플러그인은 확인할 때마다 갱신 토큰을 새것으로 바꿔 저장하므로 계속 켜 두면 유지됩니다. 비밀번호를 바꾸거나 권한을 해제하면 다시 로그인해야 합니다.
- **네이버·다음 메일은 지원하지 않습니다.** 그 서비스는 이런 방식의 읽기 연결을 제공하지 않습니다.
- **앱이나 플러그인이 꺼져 있던 동안 온 메일**은 다시 켠 뒤 첫 확인에서(아직 안 읽은 최근 2일 안의 것만) 알립니다. 본 메일은 계정마다 300통까지 기억합니다.
- 메일의 보낸 사람·제목이 말풍선과 Windows 알림에 그대로 보입니다. 화면을 남에게 보여 주는 중이면 방해 금지를 쓰세요.
- 키·토큰은 로그·저장 공간·화면 전송에 적지 않고 Google·Microsoft에 보내는 요청에만 씁니다. 저장하는 것은 본 메일의 번호, 하루 요약을 알린 날짜, 로그인 진행 정보(코드 입력 대기 중일 때만)뿐입니다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| Gmail 줄에 "설정 안 됨 — 클라이언트 ID·보안 비밀·갱신 토큰을 모두 넣어 주세요" | 세 칸 중 비어 있는 칸이 있습니다. 위 "Gmail 연결 준비"의 값을 모두 넣으세요. |
| "Gmail 로그인이 만료됐거나 취소됐어요" | 갱신 토큰이 만료됐거나 취소됐습니다(테스트 상태 7일 만료가 가장 흔합니다). 앱을 프로덕션으로 게시한 뒤 OAuth Playground에서 새 갱신 토큰을 받아 칸에 넣으세요. 말풍선으로도 한 번만 알립니다. 값을 고쳐 넣으면 곧바로 다시 확인합니다. |
| "Gmail 설정을 확인해 주세요" | 클라이언트 ID·보안 비밀이 틀렸거나, 갱신 토큰을 다른 클라이언트로 받았습니다. 토큰은 반드시 같은 클라이언트의 "Use your own OAuth credentials"로 받아야 합니다. |
| "설정을 확인해 주세요(키나 토큰이 거절됐어요)" | 토큰은 받았지만 메일 목록 요청을 Google·Microsoft가 거절했습니다(HTTP 401·403). Gmail은 Gmail API를 "사용" 상태로 바꾸지 않았거나 토큰의 범위에 `gmail.readonly`가 빠졌을 때, Outlook은 `Mail.Read` 동의가 빠졌거나 클라이언트 ID가 달라졌을 때 나옵니다. 위 준비 단계를 다시 확인하세요. 값을 고쳐 넣거나 다시 로그인하면 다시 확인합니다. |
| "요청이 거절됐어요. 플러그인의 외부 요청(net) 권한과 허용 주소가…" | ClaudeTool이 플러그인의 요청을 막았습니다. 설치 때 동의한 권한이나 접속 주소가 지금과 다릅니다. 플러그인을 지우고 zip을 다시 가져와 동의 창의 줄을 확인하세요. |
| Outlook 줄에 "설정 안 됨 — Outlook 클라이언트 ID를 넣어 주세요" | 클라이언트 ID 칸이 비어 있습니다. 위 "Outlook 연결 준비"로 얻은 ID를 넣으세요. |
| "로그인을 시작하지 못했어요(invalid_client)" 등, 또는 "로그인하지 못했어요. 클라이언트 ID와 앱 등록(공용 클라이언트 허용)을 확인해 주세요" | 클라이언트 ID가 틀렸거나, 앱 등록의 "공용 클라이언트 흐름 허용"이 꺼져 있거나, 계정 유형에 개인 계정이 빠져 있습니다. 다시 눌러도 낫지 않으니 위 2~4단계를 확인하세요. |
| "로그인하지 못했어요. 잠시 뒤 [Outlook 로그인]을 다시 눌러 주세요" | 인터넷이 끊겼거나 Microsoft 서버가 잠깐 응답하지 않았습니다. 잠시 뒤 다시 누르세요. |
| "로그인 정보를 저장하지 못했어요" | 이 PC의 안전 저장소에 쓰지 못했습니다. 잠시 뒤 [Outlook 로그인]을 다시 누르세요. 계속되면 ClaudeTool을 다시 시작하세요. |
| "로그인 시간이 지났어요" | 코드는 15분 안에 입력해야 합니다. [Outlook 로그인]을 다시 누르면 새 코드가 나옵니다. |
| "Outlook이 갱신 토큰을 주지 않았어요" | 앱 등록의 API 사용 권한에 `offline_access`가 없습니다. 위 5단계를 확인하세요. |
| "Outlook 로그인이 만료됐어요" | 갱신 토큰이 만료됐거나 권한이 해제됐습니다. [Outlook 로그인]을 다시 누르세요. 말풍선으로도 한 번만 알립니다. |
| "Outlook이 메일 목록을 주지 않았어요(HTTP 400)" 등 | Outlook이 목록 요청을 받아들이지 않았습니다. 앱 등록의 API 사용 권한에 `Mail.Read`가 있는지, 조직 계정이면 관리자가 허용했는지 확인하세요. 401·403이면 위 "설정을 확인해 주세요" 행으로 나옵니다. |
| 설정 직후 알림이 하나도 안 와요 | 첫 확인은 기존 메일을 알리지 않습니다. 설정 창의 "처음 확인이라…" 줄을 확인하고, 새 메일이 오기를 기다리세요. |
| 알림이 늦게 와요 | 확인 간격(기본 3분)이 지나야 다시 묻습니다. 설정 창의 "지금 확인"을 누르면 바로 확인합니다. |
| 말풍선만 뜨고 펫이 안 움직여요 | `choux-desk` 캐릭터를 쓰는지 확인하세요. 펫이 이미 말하는 중이거나 말풍선이 떠 있으면 신호는 버려지고 말풍선만 보입니다. 요약이 0통일 때도 펫은 움직이지 않습니다. |
| Windows 알림이 안 떠요 | "Windows 알림도 띄우기"가 켜져 있는지, 방해 금지 시간이 아닌지, 분당 6개 한도를 넘지 않았는지 확인하세요. Windows의 집중 지원이 켜져 있어도 알림이 숨습니다. |
| 말풍선의 [코드 복사]를 눌러도 붙여 넣기가 안 돼요 | 클립보드 쓰기는 분당 10번까지입니다. 잠시 뒤 다시 누르거나, 설정 창에 보이는 코드를 직접 입력하세요. |
