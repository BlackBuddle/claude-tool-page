# GitHub 알림(github-notify) 안내

GitHub에서 리뷰 요청·멘션·CI 실패·PR 닫힘/병합 알림이 오면 ClaudeTool의 펫이 알려 주고, 말풍선의 버튼으로 그 페이지를 바로 열게 하는 플러그인입니다. 쓰는 것은 두 가지입니다.

- **플러그인 zip** (`github-notify.zip`): GitHub 알림을 주기적으로 확인해 펫 신호·말풍선·Windows 알림으로 알립니다.
- **캐릭터 zip** (`choux-desk-pack.zip`): 알림 종류마다 다른 몸짓을 하는 캐릭터입니다. 없어도 알림은 옵니다.

## 준비물

- **ClaudeTool 0.4.2 이상**. 이 플러그인은 0.4.2에서 생긴 권한(Windows 알림, 링크 열기)을 씁니다.
- **GitHub 개인 액세스 토큰(classic)**. 알림 API는 세분화(fine-grained) 토큰을 지원하지 않으므로 classic이어야 합니다. 만드는 순서는 다음과 같습니다.
  1. GitHub에 로그인하고 오른쪽 위 프로필 사진 › Settings › 왼쪽 맨 아래 Developer settings로 갑니다.
  2. Personal access tokens › Tokens (classic) › Generate new token › Generate new token (classic)을 누릅니다.
  3. Note에 `ClaudeTool 알림` 같은 이름을 쓰고, 만료 기간을 고릅니다(만료되면 플러그인이 설정을 확인하라고 알립니다).
  4. 범위(scope)는 **`notifications` 하나만** 켭니다. 다른 범위는 필요 없습니다.
  5. Generate token을 누르면 `ghp_`로 시작하는 토큰이 한 번만 보입니다. 복사해 두세요. 이 창을 닫으면 다시 볼 수 없습니다. 복사한 값은 비밀번호처럼 다루고 문서·채팅에 남기지 마세요. 새어 나갔다고 의심되면 Settings › Developer settings › Tokens (classic)에서 그 토큰을 삭제하고 새로 발급해 설정 칸을 바꾸세요.
- **zip 두 개**: 플러그인 `github-notify.zip`과 캐릭터 `choux-desk-pack.zip`을 [릴리스](https://github.com/BlackBuddle/claude-tool-page/releases/tag/plugins-2026-10)에서 받습니다. 릴리스 노트의 SHA-256 값과 비교해 보세요.

## 설치

### ① 플러그인 zip 가져오기

1. ClaudeTool 설정 창 › 🧩 플러그인 › ＋ 가져오기(.zip)를 눌러 받은 `github-notify.zip`을 고릅니다.
2. 동의 창이 뜹니다. 아래 줄이 보이는지 확인하고, 괜찮으면 설치합니다.
   - 말풍선을 띄워요
   - Windows 알림을 띄워요
   - 사용자가 누른 링크를 브라우저로 열어요
   - `https://api.github.com`
3. 카드가 "실행 중"이 되면 설치는 끝입니다.

링크는 말풍선의 [열기]를 눌렀을 때만 열리고 https 주소만 열립니다. 인터넷으로 나가는 곳은 `api.github.com` 하나뿐입니다.

### ② 캐릭터 zip 가져오기(선택)

1. 설정 창 › 🐾 캐릭터 › ⤓ 가져오기(.zip)를 눌러 `choux-desk-pack.zip`을 고릅니다.
2. 가져온 캐릭터 "슈크림빵(책상)" 카드에서 "사용하기"를 누릅니다.

이 캐릭터는 신호 동작이 36개라 캐릭터 편집기의 기본 동작 한도(12개)보다 많습니다. 열기·저장·사용은 그대로 되지만, 편집하다가 새 동작을 더하려면 캐릭터 편집기 화면의 "동작 한도" 칸을 37 이상(예: 40, 최대 60)으로 올리세요(이 캐릭터는 36개라 한도가 36이면 더 못 넣습니다).

### ③ 설정 칸 채우기

설정 창 › 🧩 플러그인에서 `GitHub 알림` 카드를 고르고 칸을 채웁니다.

| 칸 | 설명 |
|---|---|
| GitHub 토큰(classic) | 위에서 만든 토큰을 붙여 넣습니다. 이 PC의 Windows 안전 저장소에 암호화해 보관하고, 설정 창에는 "저장됨"만 보입니다. |
| 확인 간격(분) | 기본 2분(1~30). GitHub가 더 긴 간격을 요청하면 그 간격을 따릅니다. |
| 열면 GitHub에서도 읽음 처리 | 켜면 말풍선의 [열기]를 누를 때 그 알림을 GitHub에서도 읽음으로 바꿉니다. [닫기]만 누르면 GitHub에서는 안 읽은 채로 남습니다. 기본은 꺼짐. |
| 리뷰 요청·멘션·CI 실패·PR 닫힘/병합 알림 | 종류별로 켜고 끕니다. 끈 종류는 신호·말풍선 없이 지나갑니다. |
| Windows 알림도 띄우기 | 말풍선과 함께 Windows 알림도 띄울지 정합니다. |
| 방해 금지 시작·끝(HH:MM) | 둘 다 적으면 그 시간 동안 온 소식을 모아 두었다가 끝나면 한 번에 알립니다. 자정을 넘겨도 됩니다(`22:00`~`07:00`). 한쪽만 적거나 모양이 틀리면 꺼 두고 설정 창에 이유를 보입니다. |

토큰을 넣으면 곧바로 한 번 확인합니다. 설정 창 안의 "지금 확인" 버튼으로 언제든 다시 확인할 수 있습니다. 설정 창에는 마지막 확인 시각과 GitHub 요청 한도 남은 수도 보입니다.

**처음 확인은 알리지 않습니다.** 토큰을 처음 넣은 날 이미 쌓여 있던 안 읽은 알림이 한꺼번에 쏟아지지 않도록, 첫 확인에서 보이는 알림은 "이미 본 것"으로만 기록하고 설정 창에 그 수를 보입니다. 그 뒤에 새로 오거나 갱신된 알림부터 알립니다.

## 알림 종류와 펫 동작

| 알림 | 이럴 때 | 펫 동작(캐릭터 `choux-desk`) | 말풍선의 [열기] |
|---|---|---|---|
| 리뷰 요청 | 누군가 내게 PR 리뷰를 요청했을 때 | `gh_review` — PR 배지 | 그 PR |
| 멘션 | 내가 또는 내 팀이 멘션됐을 때 | `gh_mention` — @ 배지 | 그 이슈·PR |
| CI 실패 | 내가 시작한 GitHub Actions 실행이 실패했을 때 | `gh_ci_failed` — X 표시와 연기, 빨간 화면 | 저장소의 Actions 쪽 |
| PR 닫힘/병합 | 알림이 온 PR이 닫히거나 병합됐을 때 | `gh_merged` — 체크 표시와 반짝임 | 그 PR |
| 그 밖 | 할당·댓글·구독 소식, 실패가 아닌 CI 소식 등 | 없음 | 없음 |

- "그 밖" 소식은 `[GitHub 소식]`으로 시작하는 말풍선 한 줄만 뜨고 펫은 움직이지 않으며 Windows 알림도 없습니다.
- PR 닫힘과 병합은 GitHub의 알림 목록만으로는 구분할 수 없어 글에 "닫힘/병합"으로 적습니다.
- 한꺼번에 여러 건이 오면 말풍선 하나에 목록으로 합쳐 보이고, 소식마다 번호가 붙은 [열기] 버튼이 생깁니다. 버튼은 5개까지입니다. 말풍선은 닫기 버튼을 누르거나 60초가 지나면 닫힙니다.
- Windows 알림은 앱의 한도(분당 6개) 안에서만 뜹니다. 다른 캐릭터를 쓰면 이 알림 동작이 없어 말풍선과 Windows 알림만 옵니다.

## 한계

- **classic 토큰만 됩니다.** 세분화 토큰은 GitHub 알림 API가 지원하지 않습니다. 조직이 classic 토큰 사용을 막고 있으면 쓸 수 없습니다.
- **GitHub 알림 목록에 있는 소식만** 알립니다. GitHub에서 저장소 구독(Watch)이나 알림 설정으로 끈 소식은 오지 않고, 웹에서 이미 읽은 알림도 알리지 않습니다.
- **실시간이 아닙니다.** 기본 2분마다 확인하고, GitHub가 알려 주는 간격(보통 60초, 서버가 바쁘면 더 길어짐)보다 자주 묻지 않습니다. "지금 확인"도 그 간격 안이면 남은 시간을 알려 줄 뿐 바로 묻지 않습니다.
- **앱이나 플러그인이 꺼져 있던 동안 온 알림**은 다시 켠 뒤 첫 확인에서 알립니다. 한 번에 최근 50건까지만 읽습니다.
- `api.github.com`만 씁니다. GitHub Enterprise Server 같은 다른 주소는 지원하지 않습니다.
- 알림 글(저장소 이름·PR 제목)이 말풍선과 Windows 알림에 그대로 보입니다. 화면을 남에게 보여 주는 중이면 방해 금지를 쓰세요.
- 토큰은 로그·저장 공간·화면 전송에 적지 않고 GitHub에 보내는 요청 머리글에만 씁니다. 저장하는 것은 본 알림의 번호와 시각, 마지막 확인 시각뿐입니다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 설정 창에 "설정에서 GitHub 토큰을 넣어 주세요" | 토큰 칸이 비어 있습니다. 위 ①~③대로 토큰을 만들어 넣으세요. |
| "설정을 확인해 주세요(키나 토큰이 거절됐어요, HTTP 401)" | 토큰이 틀렸거나 만료·폐기됐습니다. 새 classic 토큰을 만들어 칸에 다시 붙여 넣으세요. 말풍선으로도 한 번만 알립니다. |
| 같은 안내에 HTTP 403 | 토큰에 `notifications` 범위가 없거나 조직 정책이 막은 경우입니다. 범위를 확인하고 토큰을 새로 만드세요. 요청이 너무 잦아 걸린 한도 오류는 이 안내가 아니라 잠시 뒤 다시 시도합니다. |
| "요청이 거절됐어요. 토큰에 한글이나 줄바꿈이…" | 붙여 넣을 때 다른 글이 섞였습니다. 토큰만 다시 복사해 붙여 넣으세요. |
| 설정 직후 알림이 하나도 안 와요 | 첫 확인은 기존 알림을 알리지 않습니다. 설정 창의 "처음 확인이라…" 줄을 확인하고, GitHub에서 새 알림이 오기를 기다리세요. |
| 알림이 늦게 와요 | 확인 간격(기본 2분)과 GitHub가 알려 준 간격이 지나야 다시 묻습니다. 설정 창의 "지금 확인"을 눌러도 간격 안이면 남은 초를 알려 줍니다. |
| 말풍선만 뜨고 펫이 안 움직여요 | `choux-desk` 캐릭터를 쓰는지 확인하세요. 펫이 이미 말하는 중이거나 말풍선이 떠 있으면 신호는 버려지고 말풍선만 보입니다. "그 밖" 종류는 원래 펫이 움직이지 않습니다. |
| [열기]를 눌렀는데 GitHub에서 읽음으로 안 바뀌어요 | "열면 GitHub에서도 읽음 처리"를 켰는지, 토큰에 `notifications` 범위가 있는지 확인하세요. 토큰이 거절되면 설정 창에 안내가 뜹니다. |
| Windows 알림이 안 떠요 | "Windows 알림도 띄우기"가 켜져 있는지, 방해 금지 시간이 아닌지, 분당 6개 한도를 넘지 않았는지 확인하세요. Windows의 집중 지원이 켜져 있어도 알림이 숨습니다. |
