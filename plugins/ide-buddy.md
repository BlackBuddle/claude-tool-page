# IDE 코딩 참견(ide-buddy) 안내

VS Code에서 코딩하는 동안 파일을 저장했을 때, 빨간 줄(오류)이 생기거나 사라졌을 때, 테스트가 끝났을 때, 한참 손을 놓았을 때, 커밋 안 한 변경이 오래 쌓였을 때 펫이 말풍선 한 줄로 참견하는 플러그인입니다. 계정도 키도 필요 없습니다. VS Code 확장이 이 PC의 앱으로만 소식을 보내고, 인터넷으로는 아무것도 나가지 않습니다.

## 준비물

- **ClaudeTool 0.4.2 이상**
- **VS Code 1.90 이상**
- **VS Code 확장 `ide-buddy-vscode-1.0.0.vsix`.** [릴리스](https://github.com/BlackBuddle/claude-tool-page/releases/tag/plugins-2026-10)에서 받습니다. 릴리스 노트의 SHA-256 값과 비교해 보세요.
- **앱이 만든 토큰.** 확장이 "이 PC의 앱에 보내는 소식"임을 알리는 열쇠입니다. 아래 ③에서 상세 칸의 [토큰 복사]로 받습니다.

## 설치

### ① 플러그인 zip 가져오기

1. [릴리스](https://github.com/BlackBuddle/claude-tool-page/releases/tag/plugins-2026-10)에서 `ide-buddy.zip`을 받습니다. 릴리스 노트의 SHA-256 값과 비교해 보세요.
2. ClaudeTool 설정 창 › 🧩 플러그인 › ＋ 가져오기(.zip)로 그 파일을 고릅니다.
3. 동의 창에 아래 줄이 보이는지 확인하고 설치합니다.
   - 말풍선을 띄워요
   - 이 PC의 다른 프로그램이 보내는 신호를 받아요
   - Windows 알림을 띄워요

   접속하는 인터넷 주소는 없습니다. "신호를 받아요"는 앱이 이 PC 안(`127.0.0.1`)에서만 소식을 받는 통로를 여는 것이고, 토큰을 아는 프로그램만 보낼 수 있습니다.
4. 카드가 "실행 중"이 되면 끝입니다. 상세 칸의 "들어오는 연결"에 `열려 있어요`가 보여야 확장이 보낼 수 있습니다.

### ② 캐릭터 zip 가져오기(선택)

1. 설정 창 › 🐾 캐릭터 › ⤓ 가져오기(.zip)에서 `choux-desk-pack.zip`을 고르고 "사용하기"를 누릅니다.
2. 이 캐릭터를 편집기에서 열어 동작을 더 넣으려면 캐릭터 편집기 화면의 "동작 한도" 칸을 37 이상(예: 40, 최대 60)으로 올려 주세요(기본은 12개이고, 이 캐릭터는 동작이 36개라 36으로는 새 동작을 더할 수 없습니다). 열기·저장·사용은 올리지 않아도 됩니다.

캐릭터가 없어도 말풍선은 옵니다. 다른 캐릭터에는 이 플러그인용 몸짓이 없어서 몸짓만 빠집니다.

### ③ VS Code 확장 연결

1. ClaudeTool 설정 창 › 🧩 플러그인에서 `IDE 코딩 참견` 카드를 고르고, 상세 칸 "들어오는 연결"의 **토큰 복사**를 누릅니다. 토큰은 화면에 보이지 않고 클립보드에만 들어갑니다. 아래 3번에서 붙여 넣을 때까지 다른 것을 복사하지 마세요.
2. VS Code의 확장 탭 › 더보기(⋯) › "VSIX에서 설치"로 `ide-buddy-vscode-1.0.0.vsix`를 설치합니다.
3. VS Code 설정(`Ctrl+,`)에서 `ideBuddy.token`을 찾아 붙여 넣습니다.
4. 같은 설정의 `ideBuddy.port`는 기본값(47823)이 앱의 기본 포트와 같으니 그대로 둡니다. 앱의 포트를 바꿨다면(아래 "문제 해결") 이 값도 같게 바꿉니다.
5. 연결되면 ClaudeTool 설정 창의 이 플러그인 화면에 "VS Code 확장 1.0.0 연결됨 · 인사 받은 시각 …"이 보입니다. VS Code 상태 표시줄에 "IDE 참견: 연결 안 됨"이 계속 보이면 아래 "문제 해결"을 따르세요.

**토큰은 VS Code 사용자 설정(`settings.json`)에 글 그대로 남습니다.** 화면을 공유하거나 설정 파일을 올릴 때 보이지 않게 조심하고, VS Code의 설정 동기화(Settings Sync)를 쓴다면 `settingsSync.ignoredSettings`에 `ideBuddy.token`을 적어 동기화에서 뺍니다. 토큰이 새어 나갔다면 상세 칸의 **토큰 재발급**을 누르세요. 옛 토큰은 그 순간부터 쓸 수 없고, 새 토큰을 다시 복사해 붙여 넣으면 됩니다.

### ④ 설정 칸

| 칸 | 기본값 | 뜻 |
|---|---|---|
| 참견 빈도 | `normal` | `low`·`normal`·`high` 중 하나를 적습니다. 같은 종류의 참견이 다시 나오기까지 기다리는 시간이 각각 3배·1배·절반이 됩니다(기본 10분, 커밋 참견은 60분). 다른 값은 `normal`로 읽습니다 |
| 쉼 알림(분) | 30 | 편집 없이 이만큼 지나면 쉬라고 참견합니다(5~240). 확장이 편집 없는 시간을 30분 단위(30분, 60분, …)로 알려 주므로 30보다 작게 정해도 첫 참견은 30분째에 옵니다 |
| 커밋 안 한 시간(분) | 120 | 커밋하지 않은 변경이 이만큼 이어지면 커밋하라고 참견합니다(10~1440) |
| 긴 파일 줄 수 | 500 | 저장한 파일이 이 줄 수 이상이면 쪼개라고 참견합니다(100~5000) |
| 저장·커밋 참견 · 오류 참견 · 깨끗해짐 · 테스트 통과 · 테스트 실패 · 오래 쉼 | 켬 | 종류별로 끄기 |
| Windows 알림도 보내기 | 끔 | 켜면 말풍선과 함께 Windows 알림도 옵니다(분당 6개까지) |
| 방해 금지 시작·끝(HH:MM) | (비어 있음) | 둘 다 적으면 그 시간에는 참견하지 않고 모아 두었다가 끝나면 한 번에 알립니다. `22:00`~`07:00`처럼 자정을 넘겨도 됩니다. 한쪽만 적거나 형식이 틀리면 꺼 두고 설정 창에 이유가 보입니다 |

설정 창 안에는 마지막 소식을 받은 시각, 확장 연결 상태(확장 버전과 인사 받은 시각), 최근 소식이 보입니다. [새로 고침]은 화면을 다시 그릴 뿐 확장에 묻지는 않습니다. [토큰 복사 안내]는 위 ③을 짧게 보여 줍니다.

## 알림 종류와 펫 동작

| 종류 | 언제 | 말풍선 예 | 펫 동작(`choux-desk`) |
|---|---|---|---|
| 저장·커밋 참견(`saved`) | 저장한 파일이 `긴 파일 줄 수` 이상일 때, 저장 10번에 한 번, 커밋 안 한 변경이 `커밋 안 한 시간` 이상일 때 | "이 파일 640줄, 쪼갤 때 됐어." · "커밋 안 한 지 2시간 30분째야. 지금 한번 끊어 볼까?" | `ide_saved`(디스켓 배지) |
| 오류 참견(`errors`) | 저장하고 2초 뒤 모은 진단에 오류(빨간 줄)가 1개 이상 | "빨간 줄이 3개나 떴어. 보고 있지?" | `ide_errors`(벌레 배지) |
| 깨끗해짐(`clean`) | 직전 저장에 오류가 있었는데 이번 저장은 0개 | "오, 빨간 줄이 싹 사라졌어. 깔끔한데?" | `ide_clean`(체크 배지와 반짝임) |
| 테스트 통과(`tests-passed`) | VS Code 작업 중 테스트 그룹 작업이 성공(종료 코드 0)으로 끝남 | "초록불이야. 잘했어!" | `ide_tests_passed`(터지는 별 배지와 반짝임) |
| 테스트 실패(`tests-failed`) | 테스트 그룹 작업이 실패(종료 코드가 0이 아님)로 끝남 | "테스트가 실패했어. 로그부터 같이 볼까?" | `ide_tests_failed`(엑스 배지, 빨간 화면과 연기) |
| 오래 쉼(`idle-long`) | 편집 없이 `쉼 알림`분이 지남(창이 활성인 동안) | "30분째 손이 멈췄네. 스트레칭 한번 할까?" | `ide_idle_long`(Zzz 배지) |

- 한 번의 저장에서는 가장 급한 참견 하나만 나옵니다. 순서는 오류 > 깨끗해짐 > 긴 파일 > 10번에 한 번입니다. 급한 쪽이 쿨다운 중이면 아래 순서로 새지 않고 조용합니다.
- 같은 규칙의 참견은 쿨다운 안에서 다시 나오지 않습니다. 규칙마다 따로 셉니다(오류 참견 직후에도 깨끗해짐은 나옵니다).
- 말풍선 글은 종류마다 다섯 문장 안팎에서 무작위로 고릅니다. 파일 이름은 40자까지만 보입니다.
- 테스트 통과·실패는 개수가 말풍선에 나오지 않습니다. VS Code가 개수를 알려 주지 않아 종료 코드로 성공과 실패만 구분합니다.
- 한꺼번에 소식이 몰리면 앱의 말풍선 한도(분당 10개) 때문에 "소식이 N건 더 있어요" 말풍선 하나로 합쳐 보입니다.

## 한계

- **VS Code만** 지원합니다. JetBrains 같은 다른 편집기는 아직 없습니다.
- **로컬 VS Code 창에서만 앱에 닿습니다.** 원격 창(Remote-WSL·SSH·Dev Container)에서는 확장이 원격 쪽에서 실행되어 `127.0.0.1`이 ClaudeTool 앱이 있는 Windows가 아니므로, "IDE 참견: 연결 안 됨"이 계속 보일 수 있습니다.
- **테스트는 VS Code 작업(Task)으로 실행한 테스트 그룹 작업만** 봅니다. 터미널에 직접 친 명령이나 테스트 탐색기의 실행은 보이지 않습니다.
- **오류 수는 저장한 그 파일의 진단**(저장 2초 뒤)만 셉니다. 다른 파일의 오류는 세지 않고, 직전 저장의 오류 수 하나만 기억합니다. 그래서 오류가 있는 파일을 저장한 뒤 오류 없는 다른 파일을 저장하면 "깨끗해짐"이 나올 수 있습니다.
- **커밋 참견은 VS Code의 Git 확장이 켜져 있을 때만** 옵니다. 5분마다 확인하고, 변경이 처음 생긴 시각부터 잽니다.
- 앱이나 플러그인, VS Code가 꺼져 있는 동안의 사건은 사라집니다. 다시 켜도 지난 일을 되돌려 알리지 않습니다. VS Code를 닫아도 설정 창의 "연결됨"은 그대로입니다(마지막으로 받은 인사를 보여 줄 뿐 지금 켜져 있는지는 알 수 없습니다).
- 확장은 소식을 5초 묶음으로 보내고 분당 55건을 넘기지 않습니다. 연결이 거부되거나 토큰이 틀려도 조용히 넘기고 상태 표시줄에만 "연결 안 됨"을 보입니다.
- **Windows 알림은 분당 6개까지만 갑니다.** "Windows 알림도 보내기"를 켜면 말풍선과 함께 알림이 오지만, 너무 잦으면 앱이 분당 6개로 제한합니다.
- 앱의 포트를 여는 통로가 포트 충돌로 열리지 못하면 소식이 닿지 않습니다. 상세 칸이 이유를 보여 줍니다.

## 문제 해결

| 증상 | 이유와 해결 |
|---|---|
| 설정 창에 "확장이 아직 연결되지 않았어요", VS Code 상태 표시줄에 "IDE 참견: 연결 안 됨" | ① `ideBuddy.token`이 비었거나 틀렸습니다. 상세 칸의 [토큰 복사]를 다시 눌러 붙여 넣으세요 ② `IDE 코딩 참견` 카드가 "실행 중"이고 "들어오는 연결"이 `열려 있어요`인지 ③ `ideBuddy.port`가 앱의 포트(기본 47823)와 같은지 ④ `ideBuddy.enabled`가 켜져 있는지 ⑤ 원격 창(Remote-WSL·SSH·Dev Container)이 아니라 로컬 VS Code 창인지 확인하세요(원격 창에서는 `127.0.0.1`이 앱이 있는 Windows가 아니라서 닿지 않습니다) |
| 토큰을 다시 만들었더니 갑자기 끊겨요 | [토큰 재발급]을 누르면 옛 토큰은 바로 쓸 수 없습니다. 새로 [토큰 복사]를 눌러 `ideBuddy.token`에 다시 붙여 넣으세요 |
| 상세 칸에 "다른 프로그램이 이 포트(47823)를 쓰고 있어요" 같은 글이 보여요 | 앱 설정 파일(`settings.json`)의 `pluginInbound.port`를 다른 값(1024~65535)으로 바꾸고 앱을 다시 켠 뒤, VS Code의 `ideBuddy.port`도 같은 값으로 바꾸세요. 다른 프로그램이 그 포트를 쓰고 있었다면 확장이 그 프로그램에 토큰을 보냈을 수 있으니 상세 칸의 [토큰 재발급]도 하고 새 토큰을 붙여 넣으세요 |
| 참견이 하나도 안 와요 | ① 그 종류를 끄지 않았는지 ② 방해 금지 시간이 아닌지(설정 창에 모인 소식 수가 보입니다) ③ 쿨다운 안이 아닌지(기본 10분) ④ 펫을 숨겨 두지 않았는지(숨기면 말풍선이 뜨지 않습니다) ⑤ 설정 창에 확장 연결이 보이는지 확인하세요 |
| 저장 직후에는 오류 참견이 안 와요 | 진단은 저장하고 2초 뒤에 모읍니다. 그 사이에 또 저장하면 마지막 저장 기준으로 다시 셉니다 |
| 너무 자주 나와요 | "참견 빈도"를 `low`로 바꾸거나, 거슬리는 종류를 끄거나, 방해 금지 시간을 정하세요 |
| 너무 안 나와요 | "참견 빈도"를 `high`로 바꾸고, "쉼 알림"과 "커밋 안 한 시간"을 줄이세요 |
| 커밋 참견이 안 와요 | VS Code의 Git 확장이 꺼져 있거나 저장소가 열려 있지 않은 경우입니다. 변경이 "커밋 안 한 시간"만큼 이어졌는지도 보세요(5분마다 확인합니다) |
| Windows 알림이 안 와요 | 설정 창에서 "Windows 알림도 보내기"가 켜져 있는지(기본은 끔), 방해 금지 시간이 아닌지, 분당 6개 제한에 걸리지 않았는지 확인하세요 |
